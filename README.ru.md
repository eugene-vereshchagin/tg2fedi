# tg2fedi

Зеркалит новые посты Telegram-канала в аккаунт на GoToSocial.

[English version](README.md)

## Что это

Один файл на Python. Бот сидит администратором в вашем канале, скрипт
получает от Telegram новые посты и публикует их от вашего имени на вашем
сервере GoToSocial.

Пересылается:

- текст с разметкой (жирный, курсив, зачёркнутый, код, цитаты, ссылки);
- фото, в том числе альбомы до 10 штук, одним постом;
- картинки, отправленные файлом.

Не пересылается:

- «статьи» Telegram (rich-посты) — пропускаются целиком;
- видео, опросы, стикеры, голосовые (от поста с видео уйдёт только подпись);
- правки и удаления: что ушло, то ушло;
- старые посты: бот видит только то, что опубликовано после его добавления.

Написано под один канал и один аккаунт. Двух каналов одним экземпляром
не бывает, но можно запустить два экземпляра с разными ботами.

## Как работает

```
Telegram-канал ──> бот (Bot API, long polling) ──> tg2fedi ──> GoToSocial API
```

- Скрипт сам ходит к Telegram за обновлениями. Входящие порты, вебхук и
  белый IP не нужны.
- Альбом в Telegram приходит как несколько отдельных сообщений. Скрипт
  ждёт, пока они перестанут приходить, и склеивает их в один пост.
- Разметка Telegram переводится в markdown, GoToSocial его понимает.
- Очередь и отметка «что уже отправлено» хранятся в маленьком файле
  состояния, так что перезапуск ничего не теряет и не дублирует.

## Что нужно

- Сервер с Linux и systemd, Python 3.8+ и пакет `requests`. Удобнее всего
  ставить на ту же машину, где крутится GoToSocial, но не обязательно.
- Telegram-канал, где вы можете назначать администраторов.
- Аккаунт на GoToSocial и доступ к его панели настроек. Чтобы поднять
  лимит вложений, нужен ещё доступ к конфигу сервера.

## Установка

### 1. Бот в Telegram

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`,
   придумайте имя. В ответ придёт токен вида `123456:ABC-DEF...`.
2. В канале: Администраторы → Добавить администратора → найдите бота.
   Все права можно выключить, читать посты он сможет и так.

Одного бота нельзя использовать в двух местах сразу: тот, кто первым
спросит обновления, заберёт их себе. Заведите под зеркало отдельного.

### 2. Лимит вложений на сервере

У GoToSocial по умолчанию 6 вложений на пост, в Telegram альбом бывает
до 10. В `config.yaml` сервера:

```yaml
statuses-media-max-files: 10
```

После правки перезапустите GoToSocial. Лимит текста
(`statuses-max-chars`, по умолчанию 5000) трогать не нужно: пост в
Telegram не длиннее 4096 символов.

Если конфиг вам недоступен, всё равно будет работать, но альбомы
длиннее лимита сервер отклонит, и такие посты пропадут (см. «Поведение»).

### 3. Токен GoToSocial

Зайдите в панель настроек (`https://ваш-сервер/settings`) под тем
аккаунтом, **в который должны идти посты**.

1. Раздел Applications → New Application.
2. Application name: любое, например `tg2fedi`.
3. Redirect URIs: вставьте адрес, который панель показывает в рамке
   вверху страницы. Он выглядит так:
   `https://ваш-сервер/settings/user/applications/callback`.
   Без него токен прямо в панели получить не выйдет.
4. Scopes: `write`.
5. Create, затем откройте созданное приложение и запросите токен
   (Request access token). Подтвердите доступ и скопируйте токен.

### 4. Файлы и сервис

```bash
sudo apt install python3-requests      # Debian/Ubuntu
sudo mkdir -p /srv/tg2fedi
sudo cp tg2fedi.py /srv/tg2fedi/
sudo cp tg2fedi.env.example /srv/tg2fedi/tg2fedi.env
sudo chmod 600 /srv/tg2fedi/tg2fedi.env
sudo nano /srv/tg2fedi/tg2fedi.env     # вписать токены, канал, адрес сервера
sudo cp tg2fedi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tg2fedi
```

Если кладёте не в `/srv/tg2fedi`, поправьте два пути в `tg2fedi.service`.

### 5. Проверка

```bash
journalctl -u tg2fedi -f
```

Сразу после старта должна быть строка:

```
INFO start: channel my_channel -> https://example.social (private)
```

Опубликуйте в канале пост с двумя картинками. Секунд через 10–15:

```
INFO post 123 sent (images: 2)
```

## Настройки

Все настройки лежат в `tg2fedi.env`. После правки:
`sudo systemctl restart tg2fedi`.

| Переменная | Обязательна | По умолчанию | Что это |
|---|---|---|---|
| `TG_TOKEN` | да | | Токен бота от BotFather |
| `TG_CHANNEL` | да | | Username канала без `@` или числовой id вида `-1001234567890` |
| `GTS_URL` | да | | Адрес сервера, например `https://example.social` |
| `GTS_TOKEN` | да | | Токен приложения с правом `write` |
| `VISIBILITY` | нет | `private` | `public`, `unlisted`, `private` (только подписчики) или `direct` |
| `FORMAT` | нет | `markdown` | `plain` — слать голым текстом, ссылки в скобках |
| `ALBUM_WAIT` | нет | `10` | Сколько секунд тишины ждать после последней части альбома |

### Как узнать id приватного канала

У приватного канала нет username, нужен числовой id.

1. Остановите сервис: `sudo systemctl stop tg2fedi`.
2. Опубликуйте что-нибудь в канале.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найдите `"chat":{"id":-100...`. Это число и есть id.
4. Впишите его в `TG_CHANNEL` и запустите сервис.

## Поведение

- **Альбом.** Скрипт считает альбом собранным, когда `ALBUM_WAIT` секунд
  не приходит новых частей. Если альбом разваливается на два поста,
  увеличьте значение. Цена — такая же задержка публикации альбомов.
- **Сервер недоступен.** Пост остаётся в очереди, попытки повторяются
  раз в 30 секунд, пока не получится. Порядок постов сохраняется.
- **Сервер отклонил пост** (ответ 400, 404, 413 или 422: слишком много
  вложений, слишком длинный текст, файл слишком большой). Повтор не
  поможет, поэтому пост пишется в лог как выброшенный и очередь идёт
  дальше.
- **Скрипт не работал.** Telegram хранит недоставленные обновления около
  суток. После запуска посты за это время доедут, более старые пропадут.
- **Дубли.** Номера отправленных сообщений запоминаются, повторно один
  пост не уйдёт.
- **Состояние** лежит в `/var/lib/tg2fedi/state.json`. Удалять можно:
  потеряется только то, что стояло в очереди.
- **Чужие клиенты.** Ваш сервер примет 10 картинок, но серверы и
  приложения подписчиков могут показывать меньше (у Mastodon лимит 4).

## Если не работает

| В логе | Причина и что делать |
|---|---|
| `KeyError: 'TG_TOKEN'` (или другая переменная) | Не заполнен `tg2fedi.env` или неверный путь в `EnvironmentFile` |
| `getUpdates: ... Unauthorized` | Неверный токен бота |
| `getUpdates: ... Conflict` | Этим же ботом пользуется кто-то ещё или на нём висит вебхук. Снять вебхук: открыть `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook` |
| Строка `start` есть, посты не появляются | Бот не администратор канала или в `TG_CHANNEL` не тот канал |
| `GoToSocial ...: HTTP 401` | Неверный токен или у приложения нет права `write` |
| `post N dropped: ... HTTP 422` | Пост не проходит по лимитам сервера, чаще всего вложений больше, чем `statuses-media-max-files` |
| Разметка выглядит криво | Поставьте `FORMAT=plain` |

## Обновление и удаление

Обновить: заменить `/srv/tg2fedi/tg2fedi.py` и выполнить
`sudo systemctl restart tg2fedi`.

Удалить:

```bash
sudo systemctl disable --now tg2fedi
sudo rm /etc/systemd/system/tg2fedi.service
sudo rm -r /srv/tg2fedi /var/lib/tg2fedi
sudo systemctl daemon-reload
```

После этого отзовите токен приложения в панели GoToSocial и удалите
бота из администраторов канала.

## Безопасность

- В `tg2fedi.env` лежат два секрета: токен бота и токен, которым можно
  писать от вашего имени. Права на файл `600`, в git он не попадает
  (см. `.gitignore`). Если делаете бэкап сервера, эти токены окажутся
  и в нём.
- Сервис работает под отдельным временным пользователем systemd
  (`DynamicUser`), писать может только в свой каталог состояния.
- Токены в лог не попадают: тексты ошибок перед записью чистятся.
- Если токен утёк: бота перевыпустить в BotFather (`/revoke`),
  приложение удалить в панели GoToSocial и создать заново.

## Другие серверы

Скрипт использует Mastodon-совместимый API, так что с Mastodon и
родственными серверами он, вероятно, заработает с `FORMAT=plain`
(markdown там не поддерживается, а лимиты жёстче: обычно 4 вложения и
500 символов). Проверялось это только на GoToSocial.
